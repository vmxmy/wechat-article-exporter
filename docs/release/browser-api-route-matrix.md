# Browser `/api/v1` route verification matrix

Status date: 2026-07-24. This matrix maps every `/api/v1` route family
implemented in `cli/internal/web` to the Go tests that currently exercise it.
It is generated by reading the route registration in `api.go`/`api_control.go`
and the corresponding `Test*` functions, not by running coverage tooling, so
it only lists test-level evidence that was directly confirmed by inspection
on the status date above. Test names are exact and can be run individually
with `go test ./internal/web/... -run <name>` from `cli/`.

Legend for the coverage columns: `✓` means a test in that file directly
exercises the behavior for at least one route in the family; `–` means no
test was found for that behavior for that family as of the status date. This
matrix does not claim branch/line coverage percentages; it only claims the
presence or absence of at least one asserting test per cell.

## Known gaps (do not claim these are covered)

- `GET /accounts/manifest` (read path) and `GET /exports` (list) have no
  test found that specifically targets the bare read route in isolation;
  only their control-plane siblings (`/accounts/manifest/upload`,
  `/accounts/manifest/import`) and export sub-resources are directly tested.
- `GET /albums` has no dedicated invalid-input test distinct from the shared
  `parseAlbumQuery`/`parsePageValues` coverage exercised through other
  routes.
- No test in this package directly asserts the exact `error.code` value for
  every code in the §4 vocabulary of
  `docs/release/browser-api-contract.md`; several codes (`unavailable`,
  `cancelled`, `rate_limited`, `confirmation_required`, `forbidden`,
  `method_not_allowed`) are each covered by at least one test, but this
  matrix does not claim per-route exhaustive code coverage.

This matrix must be updated in the same change that adds, removes, or
relocates a route or its tests; do not let it drift from `git grep -n
'"/api/v1'` in `cli/internal/web`.
