# Browser workspace capability matrix

Status date: 2026-07-24. This matrix describes the current local product rather than the retired hosted Web product. “Supported” means the adapter has a user-facing route and executable or focused test evidence; it does not mean every CLI flag is copied into a browser control.

| Workflow | Cobra | TUI | stdio MCP | Local browser workspace | Notes / evidence |
| --- | --- | --- | --- | --- | --- |
| Select and isolate profile | Supported | Supported | Startup active profile | Supported (uses active profile) | Browser reads the selected profile; restart it after `profile use`. |
| QR login, session status, logout | Supported | Supported | Supported where policy permits | Supported | Browser uses the same application session seam; no session secret is exposed. |
| Account search, add/manage, sync, manifest transfer | Supported | Supported | Supported where policy permits | Supported | Browser account views use bounded API pages and durable jobs; discovery candidates populate the explicit local save form, and synchronization explicitly selects incremental or full mode. It streams manifest download and accepts one bounded JSON upload into an opaque staged handle before import. |
| Paginated article search/filter/select | Supported | Supported | Supported | Supported | Browser performs server-side bounded pages; article selections persist locally across pages and hand off stable IDs without loading the complete library. |
| Single article URL ingestion | Supported | Supported | Supported | Supported | Browser returns a persistent job ID. |
| Article preview, resource download, metadata/comments | Supported | Supported | Supported where policy permits | Supported | Browser queues the same persistent article/metadata/comment/resource jobs, opens only local preview state, and exposes bounded sanitized metrics/resource-detail summaries. |
| Album traversal and batch download/export | Supported | Supported | Supported where policy permits | Traversal, batch download, and selected-album export handoff supported; broader batch-export workflow not complete | Browser can list albums, preserve local selections across pages, traverse one selected album and queue its batch download; its selected-album action passes an opaque album selection to the export page. Use Cobra/TUI/MCP for broader batch-export workflows. |
| Jobs, logs and permitted controls | Supported | Supported | Supported where policy permits | Supported | Browser hands off created jobs to their stable detail route, exposes bounded job detail (job, items, logs, and lease), and renders only shared-engine permitted transitions; interrupting controls require typed scoped confirmation. An MCP-created sync job is proven visible and cancellable through the same shared profile. |
| Export HTML/Markdown/TXT/JSON/XLSX/DOCX/PDF | Supported | Supported | Supported within allowed roots | Supported | Browser authorizes a default root or descendant through an opaque directory token and validates supported format-specific controls, including HTML resource policy and batch-archive name. |
| Export manifest and verification | Supported | Supported | Supported | Supported | Browser shows safe manifest metadata and verification results. |
| Export artifact streaming / open selected output | Supported | Supported | Not applicable | Supported | Browser streams only manifest-listed artifacts through opaque artifact capabilities. Opening an export output requires that export's exact confirmation and never accepts a host path. |
| Credentials and proxy policies | Supported | Supported | Restricted by profile policy | Supported | Browser fields are write-only; it accepts one bounded Credential JSON upload without retaining the filename or secret bytes. Exact confirmation remains required for sensitive actions. |
| Preferences and language | Supported | Supported | Supported where policy permits | Supported | `display.language` accepts only `en` and `zh-CN`; browser offers both locales. |
| Backup, integrity, GC, diagnostics and diagnostic bundle | Supported | Supported | Supported where policy permits | Supported | The real web command wires maintenance facades. Browser supports backup create/verify and one-shot opaque ZIP download, integrity, GC plan plus exact-confirmation apply, diagnostics, and opaque one-shot diagnostic-bundle download. |
| Backup restore / constrained uploads | Supported | Supported | Supported within policy | Restore archive, account-manifest JSON, and Credential JSON supported; arbitrary upload not supported | Browser accepts one restore archive at a time (maximum 2 GiB), stages it privately behind an opaque handle, and requires prepare plus an exact one-time confirmation to commit. All upload entry points reject raw traversal, Windows/UNC paths, controls, and filename-normalization tricks before state changes; backup verification/restore also reject symlink ZIP entries before mutation. Manifest import uses a bounded staged JSON handle; Credential JSON is bounded and imported without filesystem staging. A successful restore closes the server; relaunch `wechat-article web`. No arbitrary host-path or general file-upload API exists. |
| Accessibility | Terminal accessibility modes | Keyboard-first terminal UI | Client-defined | Supported baseline | Browser has labelled controls, visible focus, keyboard navigation and live status; report gaps with diagnostics. |
| Transport / network surface | Local process outbound only | Local process outbound only | stdio only; no TCP | Random `127.0.0.1` loopback only | Browser uses one-time token, HttpOnly session, Host/Origin/CSRF checks and restrictive headers. |

## Completion rule

The browser workspace must remain “not complete” until the remaining partial or unsupported workflows—especially a complete batch-export workflow beyond the selected-album handoff and any intentionally excluded general file upload—have implemented user workflows and corresponding browser/API release evidence. It must not be advertised as a replacement for Cobra, TUI, or MCP before that point.

The clean-room candidate-binary receipt exercises loopback startup, authenticated embedded assets, required security headers, bounded browser API reads, a representative browser mutation, and no retired-domain observation using the sanitized loopback fixture. Separately, CI builds and launches the real Go loopback server under Playwright and verifies bootstrap/session behavior, embedded SPA and deep-route delivery, a preference mutation, and loopback-only requests; fingerprinted embedded assets are immutable-cacheable while the SPA shell remains `no-store`. See [clean-room receipts](./clean-room-receipts.md).
