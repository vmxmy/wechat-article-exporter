## Context

现有浏览器工作台是单个 Go 二进制中的嵌入式 React SPA，使用 Vite、Astryx、TanStack Query 和 TanStack Table，通过 loopback-only `/api/v1` 调用共享 `application.Application`。功能、安全和跨适配器一致性已经建立，但呈现模型仍接近底层 API：多个页面要求用户输入内部 ID、JSON、RFC3339 或后端枚举；各页面独立格式化日期、字节和状态；操作面板与数据列表分离；移动端主要依赖桌面布局压缩。

本设计把这些问题视为信息架构与展示语义缺失，而不是 CSS 框架不足。用户、实现者、安全审查者和发行工程师共同关心的约束是：功能不能倒退，内部 ID 仍需精确驱动操作，前端不能加载整库或复制业务规则，安全文件/秘密/确认边界不能放宽，最终产物仍是无远程依赖的本地单二进制。

最高验收缝采用现有 Playwright browser workflow，因为目标行为主要发生在页面层且需要同时验证文案、任务流程、响应式和可访问性。Workspace/API 测试负责证明安全投影、分页和动作契约，real-Go E2E 负责证明嵌入产物和本地运行边界。

## Goals / Non-Goals

**Goals:**

- 让普通用户只通过名称、标题、自然语言状态和引导动作完成登录、同步、浏览、导出、任务观察与设置维护。
- 统一桌面与移动资源页的信息架构、选择行为、筛选、详情、空状态、错误状态和数据格式。
- 保留专家所需的完整 ID、JSON、哈希、路径和技术状态，但只在明确技术详情或高级模式中展示。
- 让英文和简体中文在信息内容、状态语义、交互与可访问性上保持等价。
- 在不改变业务核心和安全边界的前提下，通过有界 DTO/API 投影支持名称选择器和人类可读摘要。
- 保持前端嵌入、包体预算、服务端分页和无远程资源约束。

**Non-Goals:**

- 不更换前端技术栈或引入 Tailwind。
- 不恢复远程 Web、多租户、云同步、远程 OAuth/MCP 或任何项目运营的线上依赖。
- 不改变 SQLite、对象存储、任务状态机、微信协议、导出格式或其他本地适配器语义。
- 不以体验改造为由放宽文件、秘密、代理信任、删除、恢复或 GC 安全要求。
- 不构建原生移动客户端或通用公共设计系统包。

## Decisions

### 1. 以用户概念作为主展示，以稳定 ID 作为动作身份

资源控件和表格默认显示账号名、别名、专辑名、文章标题和任务短引用，所有提交仍携带稳定 ID。账号/专辑同名时增加所属账号、别名或其他非秘密辅助信息。名称缺失时使用本地化占位和缩短标识符，不回退为毫无解释的完整 ID。

替代方案是继续直接输入 ID，实施成本低但无法满足非技术用户；另一方案是用名称作为 API 身份，会产生重名和重命名风险。因此采用“人类可读展示 + 稳定 ID 操作”的双层模型。

### 2. 增加有界选择器投影，不加载整库

若现有分页资源 API 不能支持账号/专辑选择器，Workspace 增加安全、分页、带搜索条件的选项投影。选项只返回稳定 ID、显示名称和必要辅助标签，不返回秘密、完整内部对象或无关字段。TanStack Query 缓存分页结果，输入搜索采用去抖与请求取消。

不得通过一次请求加载全部账号、专辑或文章，也不得在前端维护第二份业务索引。

### 3. 建立统一资源页骨架

账号、文章、专辑、任务、导出记录采用相同结构：页面标题和主要动作、常用筛选与“更多筛选”、激活条件摘要、结果数量和视图设置、资源表/列表、分页、粘性选中操作栏。单项详情使用侧栏或行展开，避免把详情和操作永久堆在列表下方。

这比为每页继续维护独立布局更能保证一致性，也能把响应式与可访问性规则集中验证。

### 4. 筛选分层并整合保存查询

文章默认筛选为关键词、账号、日期范围和状态；其余条件进入可发现的“更多筛选”。筛选应用后显示人类可读摘要，可逐项移除和整体清除。初始空数据与筛选无结果使用不同状态和动作。

保存查询成为文章筛选的保存视图。普通编辑使用可视化字段；原始 JSON 只在显式高级模式中出现。旧保存查询路由保持可访问并重定向或呈现兼容入口。

### 5. 选择产生上下文操作栏

列表无选择时不展示大块禁用操作表单；有选择时出现粘性操作栏，显示选中数量、最高频动作和“更多”菜单。单项动作可打开详情面板，多项动作必须明确作用范围。危险动作与常规动作视觉和菜单分组分离，并继续使用既有精确确认。

### 6. 导出采用三步状态模型

导出顺序固定为：选择范围、选择格式/格式选项、确认安全目的地并提交。每步只验证本步输入；窄屏提供持久底部主动作。默认安全目录自动选中，用户可直接继续，但底层仍使用 opaque directory capability 和服务端路径授权。

导出范围通过账号、专辑、保存查询、当前匹配结果或已选文章产生，不要求手工输入内部 ID。任务创建后展示人类可读任务名称和短引用，完整 ID 在技术详情中可复制。

### 7. 设置按用户心智分类

设置采用二级导航：常规与偏好、下载与导出、凭据、网络与代理、存储维护、诊断。危险维护操作独立区域显示影响、可恢复性和确认要求。普通分组主要使用标题、间距和分隔线，卡片保留给独立状态、权限、警告和危险操作。

### 8. 统一数据呈现与列语义

共享格式化层负责状态、任务类型、日期时间、时长、字节、数量、空值和标识符。数字按 locale 格式化，数值列右对齐并使用 tabular numerals；未知值显示 `—`，零保持 `0`。标识符、哈希和路径默认缩短，并提供完整复制/技术详情。

列声明使用 `primaryText`、`secondaryText`、`numeric`、`dateTime`、`status`、`actions`、`identifier` 和 `description` 角色。角色决定桌面对齐与截断、窄屏层级、辅助标签和可访问名称，避免各页面重复 CSS 判断。

### 9. 响应式采用信息重排而非表格压缩

桌面保留适合比较的表格。窄屏将资源行投影为列表项：主标题、次要元数据、状态、选择和动作；列显示设置隐藏。移动导航抽屉显示当前页名称和文字标签。文章标题移动端最多两行。只有 manifest 文件等本质二维内容允许局部横向滚动，整页不得溢出。

### 10. Astryx 控件与 CSS 层保持现有架构

优先使用 Astryx Selector、FileInput、TextArea、DateTimeInput、NumberInput 等控件，统一标签、帮助、必填/可选和错误位置。实施前查询所用组件的 dense contract，只有无法满足时才增加受控封装。继续维持 `reset → astryx → theme` CSS layer，不引入 Tailwind 或第二套 utility 语义。

### 11. 全局导航与术语任务化

导航分组为：首页；内容（账号、文章、专辑）；工作（任务、导出、导入）；系统（设置）。登录进入全局会话控件，保存查询进入文章视图。全局“只读”改为准确的本地隐私表述，只有实际不可变区域才使用“只读”。旧路由保持深链兼容。

首页根据状态提供下一步：未认证时登录、无账号时添加账号、有账号无文章时同步、有文章时浏览/导出、有失败任务时检查失败。运行时诊断退居次要区域。

### 12. 技术信息采用渐进披露

共享 TechnicalDetails 模式承载完整 ID、原始枚举、JSON、路径、哈希、任务租约与诊断信息，并支持复制。普通流程不得把这些字段作为必填输入。高级模式必须有清晰说明，关闭后保留已验证的语义状态，不以隐藏 JSON 作为唯一事实来源。

### 13. API 兼容与 schema 策略

现有 API 稳定 ID、请求形态和动作结果继续兼容。新增显示名称、摘要或 option endpoint 采用 additive v1 变更。若显示名称暂不可用，DTO 字段可为空并由 UI 使用可解释回退。除非无法从现有本地数据安全投影，否则不增加数据库 schema；任何新增快照字段必须可空、可回填且不成为身份事实来源。

### 14. 安全与本地运行约束不参与折中

loopback listener、bootstrap/session、Host/Origin/CSRF、安全头、敏感日志脱敏、credential transport policy、staging、opaque file capability、路径校验和 exact confirmation 全部保持。前端仍为静态嵌入 SPA，不加载 CDN、字体、analytics 或项目域名。

### 15. 浏览器状态采用安全分层持久化

文章页只把已经应用的筛选、排序和页码规范化到 URL；未应用草稿、行选择、弹窗和通知仍是临时组件状态。URL 解析与序列化集中在一个共享边界，默认值省略、非法值安全回退，用户可感知视图变化使用 history entry，机械规范化使用 replace。

导出向导只把阶段、范围类型和格式等非敏感状态放入 URL；需要刷新恢复但不适合共享的非敏感草稿使用有界 session storage。目录 capability、路径、精确确认、凭据和文章正文禁止进入任何浏览器持久化。恢复时验证状态机前置条件，缺失时回到最早有效阶段，完成或明确重置后清除草稿。

### 16. 未保存偏好由中央导航保护

偏好编辑器以最近成功加载或保存的规范化可编辑值为基线计算 dirty 状态。共享导航边界拦截内部链接、程序化跳转和浏览器历史；页面关闭与刷新只使用原生 beforeunload。站内确认使用 Astryx 可访问对话框，取消恢复焦点，确认丢弃后只恢复一次原目标。保存成功更新基线，保存失败保留草稿与 dirty 状态，全部恢复原值则自动清除。

### 17. 原生语义由共享控件边界补齐

继续以 Astryx 提供视觉、标签、焦点和错误呈现，在共享边界补充稳定 name、URL type/input mode 和明确 autocomplete 策略。二维码声明固有尺寸但保持响应式 CSS；文档为明暗模式提供 theme-color；精确技术值集中标记 `translate="no"`；数值格式统一走当前应用 locale，加载和占位文案统一使用单字符省略号。

## Risks / Trade-offs

- [名称缺失或重名导致误选] → 显示辅助标签，动作始终提交稳定 ID，技术详情可核对完整标识。
- [共享组件过度抽象拖慢交付] → 只抽取跨三个以上页面重复且有明确行为契约的模式，页面领域逻辑仍留在 feature 内。
- [移动列表与桌面表格出现行为漂移] → 两种呈现共享 query、selection 和 action model，仅改变展示投影。
- [格式化隐藏诊断细节] → 普通值使用人类格式，TechnicalDetails 保留完整原值和复制能力。
- [更多筛选降低高级条件可发现性] → 展示条件数量、激活摘要，并在空结果时直接提供编辑/清除入口。
- [导航调整破坏书签或自动化] → 保留旧路由或显式重定向，并增加深链 E2E。
- [新增名称投影扩大 API 数据面] → 只返回本地非秘密显示字段，维持分页上限、搜索限制和 contract 测试。
- [重构导致包体和首屏脚本增长] → 复用现有依赖、路由懒加载、最小 Astryx 导入，并维持 release-size 检查。
- [中英文状态映射遗漏新枚举] → 使用类型化显式映射、未知回退和单元测试，禁止直接渲染 snake_case。
- [三阶段交付期间页面不一致] → 先落共享格式化/页面模式，按完整垂直流程迁移，并在 capability matrix 标记完成度。

## Migration Plan

1. 建立共享格式化、状态、列语义、PageHeader、EmptyState、TechnicalDetails 和选择器投影，保持现有路由与流程可用。
2. 第一阶段迁移文章筛选、账号/专辑名称选择、选中操作栏和全局本地术语，并扩充桌面 Playwright 验收。
3. 第二阶段迁移首页、全局会话、保存查询、三步导出和设置分类，给旧路由增加兼容/重定向测试。
4. 第三阶段为所有资源页增加移动列表、带标签导航抽屉、统一表单和 390px/200% zoom 可访问性验收。
5. 每阶段构建并同步嵌入式 Go 资源，运行前端检查、Playwright、Go tests/vet/build、release-size 和严格 OpenSpec 验证。
6. 回滚可恢复上一版嵌入资源和展示代码；由于动作契约与持久化 schema 默认不变，Cobra、TUI、MCP 和本地资料库不需要回滚。

## Open Questions

- 账号与专辑选项能否完全复用现有分页列表，还是需要轻量 selector endpoint；实施时以网络请求数量、DTO 安全边界和复用性决定。
- 侧栏与行展开在各资源页的统一边界，以 Astryx 可访问组件能力和窄屏焦点管理验证结果为准。
- 旧保存查询路由采用重定向还是兼容页面，以避免破坏深链和浏览器后退行为的方案为准。
