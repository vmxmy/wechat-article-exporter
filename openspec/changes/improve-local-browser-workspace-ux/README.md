# improve-local-browser-workspace-ux

让本地浏览器工作台以人类可读、任务导向、响应式且可访问的方式呈现账号、文章、导出、任务和设置，同时保留现有本地安全与共享应用架构。

## Problem Statement

本地浏览器工作台已经覆盖登录、账号、文章、专辑、任务、导出和系统维护等完整流程，但当前界面仍把内部 API 与 CLI 模型直接暴露给用户：常用页面要求填写账号 ID、专辑 ID、RFC3339、JSON 和后端枚举；账号操作表单长期占据列表页面；表格、筛选、状态、空值和任务引用缺少统一的人类可读规则；移动端只压缩桌面表格，没有形成可完成工作的窄屏信息架构。

这导致用户必须理解内部标识符和实现细节才能完成同步、浏览和导出，也使中英文界面、键盘操作、危险操作和响应式布局出现不一致。问题不是缺少 CSS 框架，而是缺少统一的页面结构、数据呈现语义、交互模式和渐进披露规则。

## Solution

把浏览器工作台重构为任务导向的本地管理界面：默认界面只展示名称、标题、状态、时间、数量等用户概念，内部 ID、原始 JSON、路径、哈希和后端枚举只在技术详情中按需显示；资源页采用统一的页头、常用筛选、更多筛选、结果区、分页和选中操作栏；导出改为三步向导；设置按类别拆分；移动端把资源表转换为可读列表，并提供带当前页名称的导航抽屉。

实现继续使用 React + TypeScript + Vite + Astryx + TanStack Query/Table，不引入 Tailwind，不改变 loopback-only、本地会话、文件能力令牌、精确确认、共享 Application、SQLite 或嵌入式单二进制架构。必要时只为人类可读投影和有界选择器补充安全 DTO/API 字段，稳定 ID 继续作为内部操作契约。

## User Stories

1. 作为首次使用者，我希望首页告诉我下一步应登录、添加账号、同步还是导出，以便无需理解系统模块就能开始工作。
2. 作为回访用户，我希望首页优先显示“继续工作”和失败任务，以便迅速恢复上次操作。
3. 作为本地工具用户，我希望全局状态写成“仅在本机运行”或“数据保留在此设备”，以便准确理解隐私边界，而不会被“只读”误导。
4. 作为已登录用户，我希望从全局账号/会话入口查看、切换或退出登录，以便登录不占用永久主导航位置。
5. 作为中文用户，我希望导航、状态、任务类型、字段名和错误信息全部使用自然中文，以便不必猜测后端英文枚举。
6. 作为英文用户，我希望获得与中文界面等价的页面、状态和帮助文本，以便两种语言拥有相同能力。
7. 作为公众号管理员，我希望用账号名称或别名搜索账号，以便不必查找或粘贴账号 ID。
8. 作为公众号管理员，我希望账号选择器在同名时显示别名或辅助信息，以便准确选择目标账号。
9. 作为公众号管理员，我希望账号发现与保存通过独立入口或抽屉完成，以便账号列表不被永久表单挤压。
10. 作为公众号管理员，我希望选中账号后在附近看到同步、编辑、导出和更多操作，以便操作对象和动作关系明确。
11. 作为公众号管理员，我希望危险的删除操作与常规同步操作分开，以便降低误操作风险。
12. 作为内容运营者，我希望文章页默认只展示搜索、账号、日期范围和状态筛选，以便快速找到内容而不被高级条件淹没。
13. 作为高级用户，我希望通过“更多筛选”访问作者、内容状态、互动指标、消息类型等条件，以便保留精细查询能力。
14. 作为内容运营者，我希望看到已启用筛选的摘要或标签，并能单独移除或全部清除，以便理解当前结果为何变化。
15. 作为内容运营者，我希望“尚无文章”和“筛选无结果”呈现不同提示与动作，以便知道应同步内容还是清除筛选。
16. 作为内容运营者，我希望通过本地日期/时间控件选择时间范围，以便不必输入 RFC3339 字符串。
17. 作为内容运营者，我希望消息类型通过本地化多选控件选择，以便不必输入逗号分隔的内部值。
18. 作为内容运营者，我希望文章列表显示账号名称而不是账号 ID，以便一眼识别内容归属。
19. 作为内容运营者，我希望文章标题在桌面端合理截断、在窄屏最多显示两行，并能访问完整标题，以便兼顾信息密度和可读性。
20. 作为内容运营者，我希望文章标题可进入详情或预览，以便从列表直接继续阅读与检查。
21. 作为内容运营者，我希望阅读、点赞、分享和评论指标以清晰的统计行展示，以便不必解析一整句文本。
22. 作为内容运营者，我希望数值按语言格式化、右对齐并使用等宽数字，以便快速比较多行数据。
23. 作为内容运营者，我希望零值与未知值明确区分，未知统一显示为“—”，以便避免把缺失数据误解为零。
24. 作为批量操作用户，我希望选中文章后出现粘性上下文操作栏，以便在滚动后仍能看到选中数量和常用动作。
25. 作为批量操作用户，我希望操作栏提供最常用动作和“更多”菜单，以便主要流程清晰且高级动作仍可发现。
26. 作为键盘用户，我希望选择行、打开操作栏、进入详情和确认操作都能用键盘完成，以便无需鼠标操作。
27. 作为专辑用户，我希望用专辑名称搜索和选择专辑，并同时看到所属账号，以便不必填写专辑 ID。
28. 作为专辑用户，我希望专辑列表使用账号名称而不是内部账号标识，以便理解专辑归属。
29. 作为保存查询用户，我希望通过可视化筛选器创建和编辑保存的查询，以便无需手写 JSON。
30. 作为高级保存查询用户，我希望在明确的高级模式中查看或编辑原始 JSON，以便保留诊断和迁移能力。
31. 作为保存查询用户，我希望列表展示自然语言查询摘要，以便知道每个查询会匹配什么内容。
32. 作为导出用户，我希望导出流程分为选择范围、选择格式与选项、确认目的地三个步骤，以便每一步只处理一个决策。
33. 作为导出用户，我希望默认导出目录已经选好并可直接继续，以便常规导出无需输入路径。
34. 作为导出用户，我希望用账号、专辑、保存查询或文章搜索结果选择范围，以便不必粘贴内部 ID 列表。
35. 作为导出用户，我希望格式选项只在对应格式下出现，以便不会配置无效设置。
36. 作为导出用户，我希望在移动端底部始终看到当前步骤的主要动作，以便长表单中仍能继续或开始导出。
37. 作为导出用户，我希望任务创建后看到人类可读的任务名称和短引用，以便知道导出已进入后台处理。
38. 作为诊断用户，我希望仍能复制完整任务 ID、文章 ID、哈希或路径，以便排障时获得精确信息。
39. 作为普通用户，我希望完整 ID、哈希、路径和原始枚举默认收纳在“技术详情”中，以便日常界面保持清晰。
40. 作为任务观察者，我希望任务类型和状态本地化且语义一致，以便快速区分等待、运行、失败、部分完成和成功。
41. 作为任务观察者，我希望失败任务优先显示原因、影响范围和可执行的重试/查看动作，以便处理问题而不是只看到 failed。
42. 作为任务观察者，我希望任务详情在侧栏或行展开中出现，以便不离开列表上下文。
43. 作为设置用户，我希望设置按常规、下载与导出、凭据、网络与代理、存储维护、诊断分类，以便快速找到目标选项。
44. 作为设置用户，我希望危险维护操作独立显示并明确说明影响与可恢复性，以便不会与普通偏好混淆。
45. 作为凭据管理员，我希望凭据列表显示账号名称、类型、状态和更新时间，以便不必通过 accountId 判断归属。
46. 作为代理配置用户，我希望“凭据可信”等术语得到面向用户的解释，以便理解安全后果后再操作。
47. 作为窄屏用户，我希望导航抽屉显示当前页面名称和带文字的入口，以便知道自己所在位置。
48. 作为窄屏用户，我希望账号、文章、专辑、任务和导出记录由桌面表格重排为内容列表，以便不依赖横向滚动。
49. 作为窄屏用户，我希望每个资源条目优先显示标题/名称、次要元数据、状态和操作，以便快速扫描。
50. 作为窄屏用户，我希望列显示设置在移动端隐藏，以便不出现对列表模式无意义的控制。
51. 作为窄屏用户，我希望只有真正二维的数据才允许横向滚动，以便页面本身不会整体溢出。
52. 作为低视力用户，我希望在 200% 缩放下仍能完成主要工作流，以便无需水平滚动整个页面。
53. 作为读屏用户，我希望每页有唯一主标题、导航抽屉有名称、状态变化被宣告，以便理解页面结构与操作结果。
54. 作为键盘用户，我希望路由变化、抽屉、侧栏和确认框管理焦点并可恢复焦点，以便不会在操作后迷失位置。
55. 作为用户，我希望每个空状态都提供与当前原因匹配的下一步动作，以便从无账号、无文章、无导出或无任务状态继续工作。
56. 作为用户，我希望加载、刷新、局部失败和离线/本地服务不可用状态彼此可辨，以便知道是否需要等待、重试或重启服务。
57. 作为用户，我希望页面头部只显示标题、简短结果导向说明和主要动作，以便减少重复徽章与说明文本。
58. 作为用户，我希望普通内容用标题、间距和分隔线组织，卡片只用于独立状态、权限、警告和危险操作，以便视觉层级更自然。
59. 作为开发者，我希望所有表格列声明明确的数据语义角色，以便统一截断、对齐、响应式和可访问规则。
60. 作为开发者，我希望日期、时间、字节、时长、数量、状态、任务类型和标识符使用共享格式化层，以便各页面不再各自实现。
61. 作为开发者，我希望表单统一使用 Astryx 的选择器、文件输入、多行文本、日期时间和数字控件，以便标签、帮助、必填和错误样式一致。
62. 作为安全审查者，我希望体验改造继续使用稳定内部 ID 提交操作，以便名称变化或同名不会破坏动作准确性。
63. 作为安全审查者，我希望删除、恢复、垃圾回收、代理信任和凭据操作继续要求既有精确确认，以便体验优化不会削弱安全边界。
64. 作为隐私敏感用户，我希望浏览器继续只访问 loopback 同源 API 且不加载远程资源，以便所有界面改造仍保持本地优先。
65. 作为发行工程师，我希望重构后的静态前端继续嵌入 Go 二进制并通过资源大小检查，以便用户无需安装 Node 或额外服务。
66. 作为自动化维护者，我希望旧的登录和保存查询深链接保持兼容或提供明确重定向，以便已有书签与测试不会无提示失效。

## Implementation Decisions

- 该变更只重构本地浏览器展示层及必要的安全 Workspace DTO/API 投影，不改变领域持久化、任务引擎、微信协议、导出器或其他本地适配器语义。
- 前端继续使用 React、TypeScript、Vite、Astryx、TanStack Query 与 TanStack Table；不引入 Tailwind，也不恢复 Nuxt、远端 Web 服务、CDN、analytics 或远程字体。
- 浏览器工作台继续作为 `application.Application` 上的展示适配器。HTTP handler 只做认证、校验、映射和序列化，前端不复制业务规则。
- 稳定 ID 继续用于 API 请求、选择状态和危险操作确认，但普通页面以名称、别名、标题和短引用作为主展示。
- 当现有有界 API 不足以支持名称选择器时，增加安全、分页、可搜索的账号/专辑选项投影，禁止为了选择器把整库加载到浏览器。
- 建立共享页面模式：PageHeader、FilterBar/MoreFilters、ActiveFilterSummary、SelectionActionBar、EmptyState、TechnicalDetails、DetailPanel 和移动资源列表。
- 建立共享数据呈现层：状态、任务类型、日期时间、时长、字节、数量、空值、路径、哈希和标识符格式化。所有本地化枚举通过显式映射，未知枚举使用安全回退并保留技术值。
- 为数据列声明 `primaryText`、`secondaryText`、`numeric`、`dateTime`、`status`、`actions`、`identifier`、`description` 语义，并从语义推导对齐、截断、移动布局和辅助文本。
- 文章页默认只保留关键词、账号、日期范围和状态，其余条件进入可发现的“更多筛选”。筛选状态可总结、逐项移除和整体清除。
- 保存查询整合到文章筛选/视图。普通模式使用可视化编辑器，原始 JSON 仅在明确的高级技术模式中显示。
- 账号发现/保存迁移到专用入口或抽屉；列表选择产生就近的上下文操作栏。未选择对象时不长期展示不可用操作面板。
- 导出重构为三个步骤，并保留安全默认目录、opaque directory token、格式允许列表、持久任务和精确输出打开确认。
- 设置采用二级分类导航；危险维护操作从普通偏好中隔离，但保留所有既有能力。
- 登录从永久主导航迁移到全局会话控件；旧 `/login` 路径继续可访问。保存查询旧路径保持深链兼容或重定向到文章视图。
- 移动端使用同一查询数据源但采用资源列表呈现；列设置在移动模式隐藏。只有本质二维的数据允许局部横向滚动。
- 继续维护英文与简体中文的类型化消息目录；禁止正常界面直接显示 snake_case、后端枚举、fakeid 或未解释的安全术语。
- Astryx 控件优先于自定义原生控件；实施前查询实际使用组件的 dense contract。CSS 继续保持既有 `reset → astryx → theme` layer 顺序。
- 不要求 schema 迁移；若为显示名称快照必须增加字段，应保持可空、可回填和向后兼容，且内部 ID 仍是身份事实来源。
- 所有安全边界保持不变：loopback listener、session/CSRF、Host/Origin 检查、秘密脱敏、文件 staging、路径授权、opaque capability、精确确认及禁用远程依赖。

## Testing Decisions

- 最高验收缝为使用脱敏 loopback fixture 的 Playwright 浏览器流程测试。测试用户可见行为，不断言具体 CSS 属性或组件内部实现。
- Playwright 至少覆盖桌面宽度和 390px 窄屏：任务导向首页、名称选择器、常用/高级筛选、筛选摘要、列表/移动列表、选中操作栏、三步导出、设置分类、技术详情、空状态、错误状态和导航兼容。
- 独立 real-Go 浏览器 E2E 继续验证静态资源嵌入、深链接、真实 Workspace API、本地会话、安全头和 loopback-only 请求。
- `application.Workspace` 测试验证人类可读 DTO 投影、有界账号/专辑选项、名称缺失回退和秘密/内部字段不泄漏。
- Web API contract 测试验证分页上限、稳定 ID 动作契约、兼容字段、旧客户端可继续工作及安全响应投影。
- 前端单元测试只覆盖高价值纯逻辑：格式化、本地化枚举映射、查询摘要、短标识符、列语义和响应式行投影；不复制 Playwright 已覆盖的页面流程。
- 可访问性测试覆盖主标题、导航抽屉名称、键盘焦点顺序、焦点恢复、状态宣告、粘性操作栏、确认框和 200% 缩放无整页横向溢出。
- 测试明确区分初始空状态、筛选空状态、加载、刷新、局部错误和服务器不可用状态。
- 现有测试先例包括浏览器 workspace 与 accessibility E2E、loopback API fixture、Workspace application 测试、Web API 测试、跨适配器 parity 测试和浏览器 release verification。

## Out of Scope

- 替换 React、Vite、Astryx、TanStack Query 或 TanStack Table。
- 引入 Tailwind、恢复 Nuxt，或重新建设项目运营的线上 Web、多租户、远程 OAuth、远程 MCP 或云同步。
- 改变 loopback-only 服务、共享 Application、SQLite/object store、持久任务或单二进制嵌入架构。
- 把持久化、微信协议、导出规则、秘密管理或任务状态机移动到浏览器或 HTTP handler。
- 弱化删除、恢复、GC、代理信任、凭据、路径、上传或输出打开的精确确认和安全边界。
- 替换或移除 Cobra、Bubble Tea TUI、stdio MCP。
- 构建原生移动应用、PWA、浏览器扩展、局域网共享、协同或多用户功能。
- 改造微信协议、文章解析、导出文件格式本身或进行无关的大规模数据库迁移。
- 进行全新品牌视觉、插画系统或重动画设计。
- 抽取通用公共设计系统包；本次只建立工作台内部共享模式。
- 删除高级能力；高级 ID、JSON 和诊断信息改为渐进披露而不是移除。
