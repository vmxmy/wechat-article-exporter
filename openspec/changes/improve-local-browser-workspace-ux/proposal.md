## Why

本地浏览器工作台虽然已覆盖完整产品流程，但仍直接暴露账号 ID、专辑 ID、RFC3339、JSON、后端枚举和任务内部信息，且桌面表格、移动布局、设置与批量操作缺少统一的人类可读交互。现在需要把已经可用的功能重构为无需理解 CLI/API 内部模型即可完成同步、浏览、导出和维护的任务导向界面。

## What Changes

- 建立统一的页面头、常用/高级筛选、筛选摘要、结果区、分页、选中操作栏、详情和空状态模式。
- 正常流程使用账号名、别名、专辑名、文章标题、本地化状态和短引用；内部 ID、JSON、哈希、路径和原始枚举改为渐进披露。
- 文章页收拢高级筛选，保存查询整合进文章视图；账号发现使用独立入口；批量动作靠近所选对象。
- 导出改为三步向导；设置按类别拆分；首页按当前资料库状态提供下一步操作。
- 资源表在窄屏重排为可读列表，导航改为带当前页名称的抽屉，避免非必要的整页横向滚动。
- 建立共享的数据格式化、列语义、状态、本地化、表单、技术详情和响应式呈现层。
- 保留现有 React/Vite/Astryx/TanStack、Go 嵌入式 SPA、loopback 安全、共享 Application、文件边界和精确确认。
- 保持旧登录与保存查询深链接兼容或提供明确重定向；稳定内部 ID 和现有 API 动作语义不发生破坏性变化。

## Capabilities

### New Capabilities

- `browser-workspace-ux`: 定义本地浏览器工作台的人类可读信息架构、任务导向流程、响应式资源呈现、统一数据格式、可访问性与渐进披露行为。

### Modified Capabilities

- 无。既有 `local-browser-workspace` 的生命周期、安全、共享应用语义、文件边界和功能覆盖保持不变；本 change 在其上增加体验契约。

## Impact

- 前端应用壳、导航、首页、账号、文章、专辑、任务、导出、保存查询、设置及共享样式/组件需要重构。
- Workspace 安全 DTO 与 `/api/v1` 可能增加可选显示名称、查询摘要和有界账号/专辑选项字段；既有稳定 ID 与动作契约保持兼容。
- 英文与简体中文消息目录需要扩展并消除正常界面中的后端枚举和内部术语。
- Playwright 桌面/移动验收、可访问性测试、Workspace 投影测试、API contract 和嵌入式 real-Go E2E 需要扩充。
- 不新增前端框架、远程运行时、数据库服务、系统 SQLite 依赖或云基础设施。
