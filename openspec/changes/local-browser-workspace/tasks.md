## 2. Loopback security and lifecycle

- [x] 2.1 Bind a random IPv4 loopback port and reject wildcard, LAN, public, malformed Host, and unsupported listener configuration. `Server.Start` binds the fixed `tcp4` address `127.0.0.1:0`, and host validation requires the exact listener address and loopback peer before authorization. `TestWorkspaceBindsOnlyRandomIPv4Loopback` and `TestHostConfusionIsRejectedBeforeBootstrapOrSessionAuthorization` cover random binding and hostile Host forms.
- [x] 2.2 Implement high-entropy in-memory bootstrap token, token-to-HttpOnly-session exchange, URL token removal, session expiry, logout, and shutdown invalidation. The server creates random one-time bootstrap/session/CSRF credentials in memory, exchanges the URL token for scoped cookies and a redirect without the token, expires sessions, clears them on logout, and invalidates them on close. `server_test.go` covers successful/reused/guessed/multiple bootstrap tokens, cookie flags, expiry, logout, and cancellation shutdown.
- [x] 2.3 Implement same-origin Host/Origin/CSRF validation for mutations and request-size/content-type limits. The shared handler validates the exact Host and loopback peer before session use; mutations require the exact listener Origin, CSRF token, supported JSON/multipart shape, and bounded body size. `TestHostOriginCSRFLimitsAndLogout`, multipart upload tests, and maintenance/export mutation tests cover rejected Host, Origin, CSRF, content type, malformed, and oversized inputs.
- [x] 2.4 Add CSP, referrer, no-sniff, frame, cache-control, and error-redaction middleware with header regression tests. `server.go` applies restrictive CSP, `no-referrer`, `nosniff`, frame denial, and no-store headers to stateful responses while fingerprinted assets receive immutable caching. `server_test.go`, `asset_test.go`, preview, manifest, and artifact tests assert the headers; API tests assert generic internal errors do not serialize paths, SQL, secrets, or upstream response bodies.
- [x] 2.5 Implement `--no-open`, browser auto-open, stdout URL/stderr log discipline, signal cancellation, and bounded graceful shutdown. `commands_web.go` emits exactly one local URL to stdout, supports `--no-open`, attempts opening otherwise without leaking the bootstrap URL on failure, and serves until the Cobra context ends. `commands_web_test.go` covers both opener modes and stdout/stderr discipline; `TestSessionExpiryAndCancellationInvalidateCredentials` and lifecycle tests cover shutdown, URL invalidation, and one-shot cleanup.
- [x] 2.6 Add security tests for unauthorized access, guessed/reused token, cross-origin mutation, Host confusion, URL/log leakage, and retired-domain absence. Handler tests reject malformed and conflicting Host forms before bootstrap/session authorization, guessed and repeated/multiple bootstrap tokens without response leakage, and verify exact random IPv4 loopback URLs plus session-cookie issuance/logout clearing. Command tests preserve stdout/stderr URL discipline when browser launch fails and assert normal command output contains no retired project domains; embedded-asset tests reject retired project-domain references.

## 4. File, export, and confirmation safety

- [x] 4.1 Define service-validated export root and descendant directory-handle protocol using configured/default Downloads roots and existing output authorization. The browser now receives an opaque token for the active profile's configured root when present, otherwise the local Downloads fallback; application-level Lstat/OpenRoot/no-symlink/identity checks authorize the selected directory and reject replacement before queuing work.
- [x] 4.2 Implement streaming download responses for safe generated artifacts and bounded upload staging for account manifests, credentials, backups, and restore archives. Export artifacts and generated backup ZIPs stream through one-shot opaque handles; account manifests and restore archives use bounded private staging, while a Credential JSON file is bounded and parsed without exposing its filename or bytes. `TestMultipartUploadsRejectUnsafeFilenamesBeforeStagingOrMutation`, encoded-filename, benign-filename, manifest, credential, restore, artifact, and backup tests cover the complete browser file boundary. A restore of a generated backup uses the same restore-archive staging path; no arbitrary backup-upload route exists.
- [x] 4.3 Integrate uploaded restore archives with the existing staged transactional restore pipeline and cleanup guarantees.
- [x] 4.4 Preserve existing exact scoped confirmation behavior for deletion, job cancellation, restore, GC, credential removal, and proxy trust operations. Shared application controls require operation- and resource-scoped proofs for account/saved-query deletion, pause/retry/cancel, restore, GC, credential removal, and trusted proxy operations; resume is intentionally confirmation-free. Browser dialogs autofocus and disable their destructive action until exact input matches, restoring focus on cancellation. API and sanitized E2E cover each listed confirmation surface.
- [x] 4.5 Add path traversal, symlink/escape, oversized upload, archive abuse, failed-restore rollback, and secret non-echo regression tests. Application/API tests reject traversal and symlink/replacement races, unsafe multipart names and encoded filename tricks, oversize uploads, archive symlinks, unsafe artifact/directory handles, and archive verification/restore abuse. `TestRestoreAPIFailureDoesNotShutdown` plus restore coordinator tests preserve live state on failed restore; redaction tests prevent secret/path echo across file, export, maintenance, and restore responses.
